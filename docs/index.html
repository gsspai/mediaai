Product Requirements · Internal

把「个人自媒体矩阵」
放进同一块屏幕。

面向个人自媒体矩阵的一体化运营工作台：多平台数据汇总、爆款机会识别、限流风险预警、商务与排期协同，全部按登录人自己的配置与数据口径呈现。

内部同事使用飞书自建应用免登7 类业务角色 5 个内容平台录入 + API 混合数据源
01 / Positioning

产品定位

不是又一个数据大屏，而是把「判断」和「动作」接在一起的日常工具。

今天要解决的痛

平台后台各看一遍、Excel 手工汇总、商务进度在群里问、限流靠事后发现。信息散在五处，判断全靠人盯。

我们要给的

一屏看清平台态势与内容风险，一眼知道下一步动作归谁、到哪一步，数字按自己关心的口径算。

怎么算有效

每日打开率、风险内容平均响应时长、商务单在系统内推进率、手工汇总工时下降。

核心主张：每个数字都必须能回溯到「谁、在哪个平台、哪一天、录了什么或同步了什么」。无法回溯的展示数据不上线。
IN SCOPE

做

  • 平台账号连接与指标聚合
  • 爆款机会 / 限流风险识别
  • 商务合作与内容计划管理
  • 用户级配置（阈值、默认视图）
  • 飞书免登、审批、告警推送
OUT OF SCOPE · 本版本

不做

  • 内容生产与剪辑工具
  • 对外客户门户 / 计费
  • 广告投放与预算管理
  • 自定义拖拽 BI 看板
NON-GOAL

明确不做

  • 爬虫抓取平台数据
  • 用估算值冒充平台真实数据
  • 超出授权范围转售第三方数据
02 / Users

用户与角色

7 类角色对应同一块看板的不同默认视图；角色来自飞书用户组，入组即得权限、离组即失权。

管理员admin
全部数据、管人与配置、管理层面板
默认：总览
商务sales
客户、报价、签约与回款进度
默认：商务单
财务finance
报价复核、结算与对账
默认：商务单
策划planner
选题方向、爆款机会跟进
默认：内容计划
运营operations
账号健康、限流处置、发布排期
默认：内容计划
剪辑editor
自己的排期与待处理任务
默认：待办
分析analyst
指标口径、趋势与异常复盘
默认：总览
新同事guest
未加入业务用户组，仅可查看总览
只读
为什么不是 2 个角色：商务关心「待报价审核」，运营关心「限流风险」，剪辑只关心「这周要交什么」。用角色决定默认 Tab 与可写范围，比让所有人看同一堆信息更省认知成本。
03 / Information Architecture

信息架构

6 个页面，一层导航到底。看板是入口，其余页面是看板上每个数字的下钻终点。

路由页面职责从哪进
/login登录飞书免登入口，保留管理员本地账号兜底未登录自动跳转
/DashboardKPI、平台趋势、爆款机会、限流风险、执行列表、管理层面板登录后默认落地
/business商务合作合作单列表、阶段流转、报价审批、关联内容KPI「待报价审核」
/plans内容计划选题、排期、责任人、发布状态爆款机会「转计划」
/connections平台连接账号绑定、授权状态、同步与 CSV 导入KPI「同步异常」
/settings设置默认视图、可见平台、告警阈值、通知渠道侧栏头像菜单
导航原则：任何页面不超过两次点击回到 Dashboard；列表页必须可筛选、可分页；详情页承载「改状态」而非只是展示。

区块职责

  • KPI 4 卡：只给结论与变动，点击下钻到对应列表
  • 平台趋势：3 个主平台，5 点迷你折线，点击进平台详情
  • 机会 / 风险：每条给「为什么」与一个主动作（转计划 / 处置）
  • 执行列表：按角色默认 Tab，展示当前人该推进的事

交互规则

  • 所有数字带时间范围标签，默认近 7 天，可切 7 / 30 / 90 天
  • 空数据显示引导态，不显示 0 或假数据
  • 加载用骨架屏，失败给重试按钮，不整页白屏
  • 管理层面板仅 admin 可见，接口不返回该字段

06 / Metrics

指标口径

口径写死在文档与代码常量里，避免「同一个播放量两种算法」。

指标定义默认参数可配
播放量区间内该账号新增播放，去重同内容重复统计近 7 天时间范围
互动率（点赞 + 评论 + 转发 + 收藏）/ 播放量—否
掉速（前窗口日均播放 − 后窗口日均播放）/ 前窗口 × 100%窗口 7 天，阈值 30%阈值 / 窗口
限流判定连续 N 天播放低于基线 40%，且互动率同步下滑N=3，基线 30 日均值阈值
爆款机会分完播 0.4 + 互动率 0.3 + 增长速度 0.3，归一到 0–10≥7 进入机会列表权重后续开放
同步异常同步任务失败，或授权 7 天内到期提前 7 天提醒提前天数
时间口径：统一按用户设置的时区归一到自然日；跨零点的发布按平台侧统计日归属，不做人工调整，避免两端对不上。

09 / Non-functional

非功能需求

性能

看板首屏 < 1.5s；列表分页 20 条；CSV 1000 行导入 < 3s。

可用性

飞书故障时已登录用户可继续使用一个工作日；降级有明确提示。

安全

数据按人隔离、接口二次校验归属；平台 token 加密存储、不下发前端。

合规

仅用官方授权接口；不使用爬虫；导出数据带水印与操作审计。

10 / Acceptance

验收标准

M3 结束时逐条验收，未通过不进 M4。

身份与隔离

  • 飞书一键进入，刷新不掉登录
  • 改 URL 参数看不到他人数据（403）
  • 未入组同事只能看、不能改
  • 离职账号次日无法登录

数据真实性

  • 录入 3 天数据后看板随之变化
  • CSV 错误行返回行号与原因
  • 每条结论可下钻到明细记录
  • 空账号显示引导态而非 0

业务闭环

  • 报价走飞书审批，状态自动回写
  • 非法阶段流转被拒绝
  • 阈值命中 1 分钟内收到飞书卡片
  • 每次写操作可查到审计记录

工程质量

  • 断网 / 500 / 空数据三态齐全
  • 非 admin 接口不返回管理字段
  • 前端无 mock 常量残留
  • 构建与测试全绿
